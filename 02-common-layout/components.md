# 공통 컴포넌트

카드·버튼 기준: 샘플 03 · 내용 (사용자 제공 레퍼런스 필요). 폰트는 Pretendard Variable입니다. 헤더 로고는 아래 별도 기준을 따릅니다.

## 카드

| 항목 | 적용값 |
|---|---|
| 배경 | #FFFFFF |
| 모서리 | 4px |
| 테두리 | 없음 |
| 패딩 | 상하 30px, 좌우 40px |
| 카드 간격 | 60px |
| 3열 너비 | (1760 − 60 × 2) ÷ 3 = 약 546.67px |
| 높이 | 샘플 기준 423px, 내용에 맞춰 조정하되 같은 행은 동일 |
| 내부 주요 묶음 간격 | 20px |
| 단계 버튼과 제목 간격 | 5px |
| 카드 제목 | SemiBold 600, 30px / 행간 48px |

- 카드 순서는 단계 버튼 → 제목 → 본문 → 하단 보조 설명 텍스트입니다.
- 547px씩 3개를 배치하면 전체 폭이 1px 넘으므로 열 너비를 약 546.67px로 보정합니다.
- 내부 콘텐츠 폭은 카드 너비에서 좌우 패딩 80px를 뺀 약 466.67px입니다. 샘플의 남아 있는 제목 박스 폭 522.67px는 복제하지 않습니다.
- 반복된 샘플 문장은 실제 내용으로 교체합니다. 글자를 줄여 넣지 않습니다.

## 컴팩트 설명 카드

스크린샷·원본 그림 옆에 짧은 실행 단계나 조건을 설명할 때 선택하는 별도 유형입니다. 제목 한 줄과 본문 두 줄 정도로 하나의 행동을 설명합니다. 기존 단계 카드의 제목 30/48·본문 25/30 기본값을 대체하거나 덱 전체에 적용하지 않습니다.

### 승인 프리셋

1920×1080 Figma 장표 기준이며 크기와 행간의 단위는 px입니다.

| 항목 | 적용값 |
|---|---|
| 구조 | 세로 자동 레이아웃, 제목 → 본문, 좌측 정렬 |
| 배경·모서리 | 흰색 #FFFFFF, 모서리 4px, 테두리 없음 |
| 내부 패딩 | 상하 14px, 좌우 32px |
| 제목과 본문 간격 | 8px |
| 제목 | Pretendard Variable Bold 700, 26px / 행간 32px |
| 본문 | Pretendard Variable Regular 400, 22px / 행간 28px |
| 제목 강조 | 짧은 단계 라벨은 지정 키컬러 사용 가능. 승인 샘플은 Blue 500 (#3182F6) |
| 본문 색상 | 일반 본문 색상 유지. 승인 샘플 실측 RGB (0.12, 0.15, 0.19), 약 #1F2630 |

- 승인 샘플은 폭 1000px·높이 124px이며 내부 텍스트 폭은 936px입니다. 높이는 14 + 32 + 8 + 28×2 + 14 = 124px입니다. 이 크기는 두 줄 설명용 참조값이며 모든 카드의 고정 크기는 아닙니다.
- 한 묶음의 카드들은 같은 글자 크기·행간·패딩을 사용합니다. 텍스트는 고정 폭과 자동 높이로 두고 실제 줄 수에 맞춰 컨테이너 높이를 확보합니다.
- 내용이 길어지면 문구를 정리하거나 카드·장표 구성을 나눕니다. 이 유형의 22px보다 계속 축소하거나 자동 맞춤·자간 압축으로 밀어 넣지 않습니다.
- 짧은 단계명과 설명이 필요한 경우에 선택합니다. 긴 연구 해설, 핵심 수치, 상세 비교표를 작은 카드에 넣기 위한 우회 수단으로 사용하지 않습니다.
- 전역 타이포그래피와 일반 카드 규칙의 국소 예외입니다. 카드 밖의 제목·본문·캡션은 각자의 기존 역할별 규칙을 유지합니다.

## 내용 그룹별 텍스트 컨테이너

- 한 장 안에 의미가 다른 설명·발견·근거 묶음이 여러 개 있으면 각 묶음을 별도의 텍스트 컨테이너로 분리합니다. 예를 들어 우측에 독립적인 발견 세 가지가 있으면 컨테이너도 세 개로 만듭니다. 서로 다른 묶음을 하나의 큰 박스나 긴 텍스트 노드로 합치지 않습니다.
- 하나의 묶음에 속한 제목·설명·보조 문구는 같은 컨테이너 안에 둡니다. 문장마다 박스를 추가하거나 한 근거를 불필요하게 쪼개지 않습니다.
- 컨테이너는 편집 가능한 프레임과 텍스트로 구성하고, 같은 역할의 컨테이너끼리 모서리·내부 패딩·간격·정렬을 일관되게 적용합니다. 높이는 내용에 맞추되 겹침·잘림이 없어야 합니다.
- 선택형 내용 그룹 컨테이너 프리셋은 모서리 4px, 상하좌우 내부 패딩 24px, 인접한 그룹 컨테이너 사이 간격 20px입니다. 이는 위 샘플 03 단계 카드의 상하 30px·좌우 40px 패딩과 카드 사이 60px 규칙과 구분되는 유형별 값입니다. 다른 발표에서는 그 발표에서 확정한 컨테이너 값을 적용합니다.
- 제목 묶음과 본문 사이의 세로 간격 50px, 좌우 바깥 여백 80px, 컨테이너 내부 패딩을 서로 혼용하지 않습니다.
- 이 규칙은 구분되는 텍스트 묶음에 적용합니다. 모든 장표를 같은 카드 개수나 카드 그리드로 바꾸지 않습니다. 원본 그림·스크린샷의 비율과 필요한 정보, 이야기 흐름에 맞는 비교·프로세스·관계 다이어그램을 보존하고 설명이 필요한 부분에만 컨테이너를 배치합니다.
- 원본 시각 자료를 텍스트 카드로 대체하거나, 컨테이너에 맞추려고 근거를 삭제·왜곡하거나 글자를 축소하지 않습니다.

## 의미 강조 라벨과 컬러 결론

이 유형은 위의 샘플 03 단계 카드 하단 보조 설명과 구분되는 선택형 강조 컴포넌트입니다. 일반 보조 설명은 기존 규칙대로 배경 없는 텍스트를 유지합니다.

- 한 장의 핵심 역할·해석·결론을 눈에 띄게 구분할 때, 짧은 라벨을 버튼처럼 채색하고 옆에 결론 문장을 둡니다. 기본적으로 한 장의 핵심 강조 지점 한 곳에 사용하며 일반 설명 문단 모두에 반복하지 않습니다.
- 이것은 클릭 동작 없는 의미 라벨입니다. 버튼처럼 보인다는 이유로 링크·호버·클릭 기능을 추가하지 않으며, 실제 동작이 요청된 경우에만 인터랙션을 연결합니다.
- 짙은 강조색 배경의 밝은 라벨 글자와, 같은 강조색의 결론 글자를 짝지어 하나의 강조 묶음으로 읽히게 합니다. 밝은 면 위에 밝은 글자를 쓰지 않고 실제 배경과 충분한 명도 대비를 확인합니다.
- 라벨 배경·연결 화살표·핵심 결론 글자는 현재 장표·사례의 지정 키컬러를 공유합니다. 덱 전체를 한 색으로 통일하거나 다른 사례의 색을 그대로 복사하지 않습니다. 아래 #522654는 승인 샘플의 국소 값이며 Blue 계열의 전역 규칙을 대체하지 않습니다. 같은 사례 안의 같은 역할에는 같은 색·크기·굵기를 유지합니다.
- 라벨은 짧게, 결론은 한 문장으로 씁니다. 라벨과 결론을 같은 가로 자동 레이아웃에 넣고 수직 중앙 정렬합니다. 라벨 폭은 문구와 패딩에 맞추며, 긴 결론을 담기 위해 글자를 줄이지 않습니다.
- 아래 실측 비대칭 패딩을 그대로 사용하는 것과, 다른 문구에 맞춰 광학 정렬을 조정하는 것을 구분합니다. 임의의 공백 문자·빈 줄로 정렬하지 않습니다.

### 승인 프리셋: 역할 라벨 + 컬러 문장

1920×1080 장표 기준, 단위는 px입니다. [확산 흐름과 문제·대응 양식](../references/expansion-problem-response.md)의 하단 강조에 적용된 값입니다.

| 요소 | 참조값 |
|---|---|
| 바깥 행 | 1760×68, 가로 자동 레이아웃, gap 0, 왼쪽 정렬·수직 중앙, 배경 없음 |
| 라벨 | 180×50, 행 내부 X 0 / Y 9, 모서리 0 |
| 라벨 배경 | RGB (0.32, 0.15, 0.33), 약 #522654 |
| 라벨 패딩 | 상 4 / 우 17 / 하 2 / 좌 22 |
| 라벨 내부 정렬 | 가로·세로 중앙, 내부 gap 10 |
| 라벨 글자 | Pretendard Variable SemiBold 600, 28 / 44, #F2F5FA |
| 라벨 문구 예 | GTM의 역할 |
| 설명 컨테이너 | 1580×68, 행 내부 X 180 / Y 0, 상하 12·좌우 28 패딩, 내부 gap 24 |
| 설명 외관 | 배경 없음, 모서리 4는 채움이 없어 보이지 않음 |
| 설명 글자 | Pretendard Variable SemiBold 600, 28 / 44, 라벨 배경과 동일한 강조색 |
| 설명 텍스트 폭 | 컨테이너 내부 가용 폭 1524, 고정 폭 또는 FILL 후 높이 자동 확장 |

샘플의 라벨 텍스트는 141×44였으므로 22 + 141 + 17 = 180, 4 + 44 + 2 = 50입니다. 다른 문구에서는 이 텍스트 폭을 강제하지 않고 필요한 폭을 계산합니다. 샘플에 남아 있던 설명 텍스트 폭 1704는 컨테이너 내부 폭을 초과하므로 재사용하지 않습니다. 새 양식에는 1580 − 28×2 = 1524를 적용하고 실제 렌더링에서 잘림·넘침을 확인합니다.

## 카드 텍스트 강조

- 카드 제목의 핵심 단어 또는 짧은 구절에 Blue 500 (#3182F6)을 적용합니다. 나머지는 Grey 900을 유지합니다.
- 카드 본문은 Regular 400을 기본으로 하고, 강조할 핵심 단어 또는 최대한 짧은 구절만 Bold 700으로 표시합니다.
- 문장 전체를 굵게 만들지 않으며, 강조 구간도 본문 크기 25px·행간 30px·Grey 900을 유지합니다.

## 헤더 로고

### 공통 슬롯

- 좌측 상단은 작성자 브랜딩 로고, 우측 상단은 교육기관·대상 청중 로고의 자리입니다. 실제 브랜드는 이번 발표의 지정값으로 결정하며 임의로 다른 브랜드를 넣지 않습니다.
- 헤더 프레임은 장표 기준 X=80, Y=50, W=1760, H=44입니다. 좌측 로고의 왼쪽 끝은 X=80, 우측 로고의 오른쪽 끝은 X=1840에 맞춥니다.
- 원본 로고의 가로세로 비율과 브랜드 색상을 유지합니다. 헤더 높이 안에서 수직 위치를 맞추며 가로세로를 따로 늘리거나 로고 글자를 다른 폰트로 재작성하지 않습니다.
- 표지·뒤표지·목차·간지를 포함한 모든 장표에 적용합니다. 기존 헤더가 있으면 재사용하고 누락된 장표에만 추가해 중복을 피합니다. 전용 샘플의 명시적 예외가 있으면 해당 범위만 적용합니다.
- 로고의 실제 경계와 헤더·챕터명·표지 콘텐츠가 겹치지 않는지 확인합니다.

### 로고 설정

발표자가 사용할 권한이 있는 로고를 지정한 경우에만 배치합니다. 실제 로고·파일·좌표는 비공개 발표 입력에서 지정하고 원본 비율을 유지합니다. 기본 공개본에는 특정 작성자나 교육기관 로고가 포함되지 않습니다.

## 비교 위계와 사례별 시각 자료

- 공통 분류 기준은 한 번만 상위에 표시하고, 각 카드의 고객·대안·모델 이름은 하위 제목으로 둡니다. 둘을 같은 문구·같은 강도의 버튼으로 반복하지 않습니다. '버튼화'는 시각적 라벨을 뜻하며 클릭 기능을 뜻하지 않습니다.
- 두 개념의 차이와 '함께 쓰는 방법'을 설명하면, 두 개념을 나란히 비교하고 통합 방법은 하단 결론으로 분리합니다. 서로 다른 논리 수준을 같은 크기의 세 카드로 놓지 않습니다.
- 브랜드 사례의 식별 로고는 같은 덱에서 사용자가 확정한 사례 로고 위치·비율에 맞춥니다. 작성자·교육기관 헤더 로고와 다른 역할이며 그 슬롯을 임의로 덮어쓰지 않습니다. 새 사례를 추가할 때 로고 누락도 확인합니다.
- 모델별 특징을 설명하는 사진은 각 모델 아래, 브랜드 예시는 해당 고객 유형 아래 등 설명 대상에 붙입니다. 관련 브랜드의 아무 사진이나 넣어 근거를 대신하지 않습니다.
- 일반 카드의 고정 글자 크기를 모든 비교표·화면 안내에 강제하지 않습니다. 해당 유형의 승인된 프리셋을 사용하며, 넘침을 이유로 무제한 축소하지 않습니다. 유형별 적용 원칙는 [교육 장표 수정 사례](../references/course-revision-patterns.md)를 참고합니다.


## 기존 완성 장표에 새 사례를 붙일 때

- 동일 유형의 최신 사용자 완성 카드를 실제로 읽고 복제합니다. 카드만 아니라 장표 배경·제목 라벨·본문 굵기·하단 결론까지 대응시킵니다. 기억에 의존해 비슷한 HEX, 회색 면, 테두리, 큰 둥근 모서리를 새로 만들지 않습니다.
- 기존 채움·텍스트가 색상 변수에 연결되어 있으면 그 연결을 보존합니다. 브랜드 고유색·사진·표지 그라디언트까지 공통 파란색으로 덮지 않습니다.
- 위의 일반 카드와 컴팩트 설명 카드는 별개입니다. 사용자가 특정 비교 카드의 제목을 버튼화했다고 해서 모든 화면 설명 카드의 제목까지 자동 변환하지 않습니다. 현재 요청의 범위와 같은 역할의 실제 참조를 따릅니다.
- 텍스트는 고정 폭과 자동 높이로 두고, 실제 줄 수와 패딩을 포함해 컨테이너 높이를 확보합니다. 글자 축소나 빈 줄로 맞추지 않습니다.
- 카드 유형별 국소 값과 검수 원칙은 [최종 제작 검수](../references/final-production.md)를 참고합니다.
