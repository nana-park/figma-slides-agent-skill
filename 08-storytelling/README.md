# 스토리 구성

아래 입력 양식에 필요한 내용을 작성합니다. 이미 확정된 값은 유지하고 빈칸만 확인합니다.

## 입력 양식

- 논리 전개 결정 방식: [입력]
- 전체 이야기 순서: [입력]
- 전달 관점·문체: [입력]
- 강조할 논점·예상 반론 대응: [입력]
- 제목 표현·장표 간 연결 방식: [입력]

## 작성 원칙

전체 이야기 흐름을 정하며, 개별 장표의 실제 내용은 09에 기록합니다. 논리 전개를 AI에 맡겨도 사실과 수치를 만들도록 허용하는 것은 아닙니다.

[전체 안내](../README.md)

## 입력 안내

- 필수: 논리 전개 결정 방식 (직접 지정/AI 제안).
- 조건부: 전체 이야기 순서 (직접 지정 시. 결론→근거→실행 등).
- 필수: 전달 관점·문체 (컨설팅/교육/영업 등 또는 AI 결정).
- 선택: 강조할 논점·예상 반론 대응.
- 선택: 제목 표현·장표 간 연결 방식.

이미 기록된 값은 다시 묻지 않습니다. 필요한 값이 없으면 질문하고 이 문서에 반영합니다. 선택 항목은 비워도 되며, 작성 예시는 확정값이 아닙니다.

## 교육 강의의 이야기 전개

교육 강의안은 [교육 스토리 흐름](../references/teaching-story-flow.md)을 읽고, 각 장표가 앞 장의 어떤 질문을 받아 다음 장의 어떤 질문을 여는지 설계합니다. 개념→사례→실습 순서를 모든 단원에 기계적으로 강제하지 않습니다.

- 도입 질문, 대조, 정의, 근거, 체험, 회고, 팀 적용 중 이번 학습목표에 필요한 기능을 선택합니다. 장표를 추가할 때는 앞뒤 연결에서 맡는 기능이 있어야 합니다.
- 개념을 처음 쓰기 전에 의미를 설명하고, 방법·입력 항목·예시를 개념 자체와 혼동하지 않습니다. 연관된 프레임워크도 논리적 위계와 목적을 구분합니다.
- 활동은 배운 개념을 자기 서비스에 적용할 산출물과 연결합니다. 체험은 무엇을 느꼈는지 끝내지 않고, 그 경험이 보여준 개념·한계·다음 판단을 회고하게 합니다.
- 진단용 선행 활동은 학습 전 초안을 남기고 학습 후 다시 검토하도록 설계할 수 있습니다. 처음부터 완성 답안을 요구하는 활동과 구분합니다.
- 앞 날짜에서 익숙해진 사례는 인지 부담을 줄이는 데 재사용하고, 관점 차이를 드러내려면 대비 사례를 추가합니다. 익숙한 브랜드라는 이유로 근거 없는 분석을 사실로 쓰지 않습니다.
- 다른 날짜에 본격적으로 다룰 내용은 이번 시간의 학습목표에 필요한 연결만 남깁니다. 예정된 후속 수업을 대신하는 내용으로 현재 단원을 채우지 않습니다.

- 학습자가 새 도구로 산출물을 만들어야 한다면 개념 이름과 빈 양식 사이에 작성 과정 또는 완성 예시를 보여줍니다. 단, 학습 전 진단 활동으로 초안을 남기려는 명시적 목적은 구분합니다.
- 수업 시간은 장수만으로 추정하지 않습니다. 설명 깊이, 개인 생각, 팀 의논, 발표·회고 시간을 따로 보고 실제 이전 수업의 소요 시간으로 조정합니다. 모자란 시간을 무관한 개념이나 불필요한 장표로 채우지 않습니다.
