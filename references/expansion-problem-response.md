# 확산 흐름과 문제·대응 양식

## 언제 사용하는가

제품이나 서비스의 사용 범위가 단계별로 넓어지고, 그 과정에서 드러난 문제와 대응을 함께 설명할 때 선택합니다. 도입·확산 사례, 파일럿에서 조직 전체로의 확대, GTM 학습 과정을 한 장에 연결하는 데 적합합니다.

상단은 **어디까지 확산됐는가**, 중단은 **어떤 문제가 생겼고 무엇을 바꿨는가**, 하단은 **이 사례가 보여주는 역할은 무엇인가**를 답합니다. 단순한 세 개념 비교나 수치 차트 대신 쓰는 만능 카드 양식은 아닙니다.

## 구성과 읽는 순서

1. 상단: 세 개의 짧은 단계 카드와 두 개의 오른쪽 화살표로 흐름을 보여줍니다. 단계에는 고객·조직·사용 범위의 변화만 넣고 설명 문단은 아래로 내립니다.
2. 중단: 왼쪽에는 확산으로 드러난 문제, 오른쪽에는 그 문제에 대응한 기능·운영·도입 안내 변경을 배치합니다. 양쪽의 같은 순서에 대응하는 내용을 두어 관계가 읽히게 합니다.
3. 하단: 버튼형 의미 라벨과 같은 강조색의 한 문장 결론을 가로로 둡니다. 흐름과 대응의 의미를 해석하고 세 단계의 이름을 다시 나열하지 않습니다. 클릭 기능 없는 라벨의 상세 값은 [의미 강조 라벨과 컬러 결론](../02-common-layout/components.md#의미-강조-라벨과-컬러-결론)을 따릅니다.

상단은 하나의 흐름, 중단은 두 개의 의미 그룹, 하단은 하나의 결론으로 구분합니다. 각 설명 문단은 독립된 편집 가능한 텍스트 노드로 유지하되, 문장마다 별도 카드를 만들지는 않습니다.

## 승인 샘플의 참조 프리셋

1920×1080 고정 슬라이드용 프리셋입니다. 반응형 웹의 breakpoint나 모바일 재배치 규칙은 없습니다. 아래 값은 이 양식에 한정하며 [공통 컴포넌트](../02-common-layout/components.md)의 단계 카드·내용 그룹 프리셋과 혼합하거나 전역 토큰으로 승격하지 않습니다. 다른 발표에서는 확정된 브랜드·폰트·공통 헤더와 푸터를 보존합니다.

좌표는 장표 기준이며 크기·글자·행간 단위는 px입니다.

폰트는 Pretendard Variable입니다. 제목·챕터명·단계 제목·카드 소제목은 Bold 700, 일반 본문·화살표는 Regular 400을 사용합니다. 이 양식의 크기·굵기는 참조 프리셋이며 다른 유형의 공통 타이포를 바꾸지 않습니다.

| 영역 | 참조값 |
|---|---|
| 장표 | 1920×1080 |
| 제목 | 44px / 행간 64px |
| 챕터명 | 24px / 행간 32px |
| 제목 묶음과 본문 사이 | 50px |
| 본문 프레임 | X 80, Y 360, W 1760, H 596 |
| 본문 자동 레이아웃 | 세로, 영역 간 간격 16px |
| 상단 흐름 행 | 1760×96, 가로, 왼쪽 정렬(MIN), 항목 간격 12px, 수직 중앙 |
| 단계 카드 | 544×96, 모서리 8px, 패딩 20px |
| 단계 카드 채움 | RGB (0.91, 0.87, 0.94), 약 #E8DEF0 |
| 단계 제목 | 폭 504px, 30px / 행간 40px, 중앙 정렬 |
| 화살표 | 편집 가능한 → 텍스트, 28×44px 박스, 크기 32px. 두 화살표는 역할 라벨 배경·핵심 결론 글자와 같은 키컬러를 공유합니다. 현재 샘플 값은 SOLID RGB (0.32, 0.15, 0.33), 약 #522654, 불투명도 100%, stroke 없음이며, 다른 장표·사례에서는 그 사례의 지정 키컬러를 사용합니다. 덱 전체를 이 색으로 통일하거나 보라색 자체를 공통 고정값으로 사용하지 않습니다. |
| 중단 설명 행 | 1760×400, 가로, 간격 24px |
| 문제·대응 카드 | 각각 868×400, 흰 배경, 패딩 32px, 내부 간격 24px |
| 카드 소제목 | 34px / 행간 44px |
| 카드 본문 | 30px / 행간 44px |
| 하단 강조 행 | X 80, Y 888, 1760×68, 가로 gap 0, 왼쪽 정렬·수직 중앙, 배경 없음 |
| 역할 라벨 | 180×50, 행 내부 Y 9, 짙은 강조색 배경·밝은 글자 |
| 결론 설명 컨테이너 | 1580×68, 상하 패딩 12px·좌우 28px, 배경 없음 |
| 결론 본문 | 가용 폭 1524px, 28px / 행간 44px, SemiBold 600, 라벨 배경과 동일한 강조색 |
| 출처·푸터 | Y 984 이후의 기존 영역 유지 |

본문 높이는 96 + 400 + 68 + 16×2 = 596px이며 아래끝은 Y 956입니다. 이 프리셋의 하단 위치는 공통 본문 한계와 다를 수 있는 국소 값입니다. 공통 마스터의 하단 한계가 Y 944로 확정된 발표에서는 그대로 넘기지 말고 이 예외의 채택 여부를 확인하거나 내용을 재구성합니다.

흐름 행 내부 X는 카드 0 / 596 / 1192, 화살표 556 / 1152입니다. 544×3 + 28×2 + 12×4 = 1736px이므로 오른쪽에 24px가 남는 것이 승인 샘플의 실측입니다. 이를 자동으로 space-between 정렬로 바꾸거나 간격·패딩에 분산하지 않습니다.

## 제작·교체 원칙

- 가로 흐름은 단계 카드 → 화살표 → 단계 카드 → 화살표 → 단계 카드 순서의 자동 레이아웃으로 구성합니다. 화살표는 흐름의 방향을 나타내며 장식용 큰 도형이나 연결 없는 독립 아이콘으로 바꾸지 않습니다.
- 중단의 두 카드는 높이·폭·패딩·본문 위계를 같게 유지합니다. 문제와 대응이 각각 무엇인지 소제목에서 드러내고 문단별 대응 순서를 맞춥니다.
- 본문 텍스트는 고정 폭과 자동 높이를 사용합니다. 단계 라벨은 짧게 다듬고, 설명이 넘치면 중복을 정리하거나 장표를 나눕니다. 글자 축소·자간 압축·자동 맞춤으로 해결하지 않습니다.
- 하단의 의미 라벨과 컬러 결론은 한 강조 묶음입니다. 실제 버튼 동작이나 링크는 추가하지 않습니다.
- 결론은 한 줄 기준입니다. 여러 줄이 필요하면 결론 박스만 늘려 푸터를 침범하지 말고 전체 본문 높이와 출처 영역을 함께 검토합니다.
- PPTX에서는 고정 슬라이드 크기에 맞춰 비례 변환합니다. px 값을 pt로 그대로 옮기지 않습니다.
- 상단의 규모·사용자 수는 실제 근거가 있을 때만 넣습니다. 샘플의 회사명·숫자·문구는 새 발표의 사실로 복제하지 않습니다.
- 문제와 변경 사이의 인과관계가 확인되지 않으면 단정하지 않습니다. 단지 시간순으로 일어났다는 이유로 변경이 특정 문제를 해결했다고 쓰지 않습니다.
- 실제 사례의 출처는 [텍스트 규칙](../02-common-layout/text-rules.md)에 따라 장표 하단에 저자(연도)로 표시하고 상세 서지·원문 링크는 노트에 남깁니다. 작성자 저작권과 근거 출처를 구분합니다.

## 교체 예시

아래는 디자인 사용법을 설명하기 위한 가정이며 실제 회사 사례나 측정 결과가 아닙니다.

- 제목: 사용 범위가 넓어지면서 탐색과 도입 안내를 보완했습니다.
- 상단: 소규모 파일럿 → 여러 부서 → 조직 전체
- 왼쪽 소제목: 확산으로 드러난 문제
  - 항목이 늘어나 새 사용자가 자신에게 필요한 공간을 찾기 어렵습니다.
  - 처음 사용하는 사람과 도입을 담당하는 관리자가 필요로 하는 안내가 다릅니다.
- 오른쪽 소제목: 구체적으로 바꾼 기능과 안내
  - 공간의 설명과 이용 정보를 목록에 표시해 선택을 돕습니다.
  - 개인용 시작 안내와 관리자용 도입 자료를 나눕니다.
- 하단 라벨: GTM의 역할
- 하단 결론: 사용 범위를 넓히는 일에는 제품 개선과 도입 지원이 함께 필요합니다.

## 검수 체크리스트

- 상단 세 단계만 읽어도 확산 방향과 범위가 이해되는가?
- 화살표가 단계 사이에서 수직 중앙에 있고 라벨과 겹치지 않는가?
- 문제와 대응이 같은 순서로 연결되며 설명 카드의 크기·패딩·위계가 같은가?
- 문단은 각각 편집 가능하고 한 문장씩 불필요한 박스로 분리하지 않았는가?
- 하단 라벨과 결론이 수직 중앙에 정렬되고 같은 강조색으로 연결되는가?
- 하단 결론이 사례의 해석을 한 문장으로 전달하며 실제 버튼 기능이 추가되지 않았는가?
- 실제 렌더링에서 텍스트 잘림·겹침이 없고 본문과 출처·푸터가 분리되는가?
- 샘플 숫자·회사·가정을 사실로 복제하지 않았고 적용한 국소 예외를 기록했는가?
