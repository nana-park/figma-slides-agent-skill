# 기존 제작 스킬 연결

## 역할 분담

- 이 저장소: 입력 수집, 필요한 질문, 스토리 구성, 사용자 디자인 규칙, 최종 제작 요청 정리.
- 설치된 제작 스킬: 실제 파일 생성·편집, 요소 배치, 렌더링, 형식별 검증.
- 제작 스킬의 일반 디자인 권장은 사용자의 확정 규칙을 대체하지 않는다. 도구 사용에 필요한 기술 지침은 그대로 따른다.

## 제작 대상별 선택

| 사용자 요청 | 사용할 스킬 | 적용 방법 |
|---|---|---|
| Figma 발표 자료 생성·편집 | figma:figma-use-slides 및 figma:figma-use | 기본 제작 경로. 새 파일이 필요하면 figma:figma-create-new-file도 읽는다. |
| PowerPoint/PPTX 생성·편집 | presentations:Presentations | 문서 제작의 기본 지침으로 사용한다. 선택한 제작 방식에 PPTX 세부 처리·검증이 필요하면 pptx도 읽는다. |
| Figma와 PPTX 모두 | Figma 경로와 필요한 PPTX 경로 | 내용·디자인 기준은 하나로 유지한다. 내보내기 지원부터 확인하고, 별도 재제작이 필요하면 차이를 설명한다. |
| 프롬프트만 생성 | 이 저장소의 SKILL.md | 실제 제작 도구는 실행하지 않는다. |

이름과 경로는 현재 세션의 스킬 목록에서 찾는다. 버전이 붙은 설치 경로를 고정하지 않는다. 스킬 파일의 존재만으로 해당 MCP·라이브러리·로그인·내보내기 기능이 실행 가능하다고 가정하지 않는다.

## 실행 순서

1. 사용자가 제작까지 요청했는지 확인한다. 연결 규칙 수정이나 프롬프트 조립 요청은 제작 요청이 아니다.
2. 01~10 입력과 02 고정 규칙을 읽고, 빠진 핵심 정보만 체크리스트 규칙에 따라 질문한다.
3. 제작 대상은 명시적 요청과 10을 따른다. 별도 변경 요청이 없으면 이 프로젝트의 기본 대상은 Figma다. 사용자에게 내부 스킬이나 라이브러리 선택을 요구하지 않는다.
4. 해당 스킬의 SKILL.md를 현재 환경에서 읽고 필요한 참조만 추가로 읽는다. 실제 코드 작성이 필요하면 호스트의 코딩 지침도 따른다.
5. Figma에서는 [캔버스 장표 배치](../10-production-rules/canvas-layout.md)에 따라 현재 페이지의 행·열·챕터 경계를 먼저 확인하고 추가·이동 장표를 확정된 본문 순서 안에 배치한다. 정밀한 폰트·좌표·브랜드 규칙을 적용할 수 있는 경로를 우선한다. use_figma가 제공되면 관련 스킬을 따라 사용한다. generate_deck와 use_figma로 같은 덱을 중복 생성하지 않는다. 정밀 규칙을 지원하지 않는 템플릿 생성으로 조용히 대체하지 않는다.
6. PPTX에서는 bundled runtime 경로를 load_workspace_dependencies로 확인하고, presentations 스킬의 현재 제작·렌더링 절차를 따른다. pptx의 도구 안내와 다르면 호스트 지침과 기본 제작 스킬의 지침을 우선한다.
7. 확정된 목적·본문·데이터·디자인 규칙·레이아웃·레퍼런스·예외·출력 조건을 제작 스킬에 한 번에 전달한다. 이미 답한 질문이나 승인한 구성안을 다시 묻지 않는다.
8. 전달된 범위 안에서 AI가 구도·시각적 위계·차트 선택 등 미지정 세부를 판단한다. 사실·수치·출처를 창작하거나 명시된 디자인 규칙을 완화하지 않는다.
9. 결과물의 실제 렌더링/스크린샷과 구조를 검사하고, 문제 부분만 수정한다. 편집 가능한 요소·실제 출력 형식·남은 한계를 확인해 링크 또는 파일로 전달한다.

## 사용자 규칙 보존

폰트·화면 크기·컬러는 01-design-system/README.md, 장표 내부 배치·좌표는 02-common-layout/README.md, 캔버스의 장표 간 배치는 10-production-rules/canvas-layout.md를 기준으로 읽는다. 사용자 규칙은 연결 설정을 위해 변경하지 않는다.

- Pretendard Variable, 1920x1080, 페이지 번호·출처 위치와 정렬 등 지정된 값을 전달한다.
- PPTX의 좌표 단위가 다르면 1920x1080 기준 좌표를 문서 단위로 비례 변환한다. 1920이나 1080을 인치 단위로 직접 사용하지 않는다.
- 지정 폰트를 사용할 수 없으면 다른 폰트로 몰래 대체하지 않는다. 사용 가능 여부와 해결이 필요한 제약을 알린다.
- 원문의 폰트 크기 표현 등 해석에 따라 결과가 달라질 수 있는 규칙은 전달 과정에서 임의로 재작성하지 않는다. 실제 제작을 막는 충돌이 발생했을 때만 구체적으로 확인한다.
- 일반적인 여백·템플릿 추천보다 사용자가 정한 밀도·정렬·적용 범위를 우선한다.

## 완료 기준

실제 산출물이 존재하고 검증했을 때만 제작 완료라고 말한다. 설치·로그인·도구 부재로 실행할 수 없다면 준비된 프롬프트와 막힌 단계를 전달한다. 이 연결 규칙을 저장한 것만으로 전역 스킬 설치나 제작 실행이 끝났다고 말하지 않는다.
