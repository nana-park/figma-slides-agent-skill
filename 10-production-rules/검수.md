# 검수 규칙

공개본의 일반 제작 및 검수 규칙입니다. 체크박스 입력 양식이 아니라 제작 후 확인할 기준입니다. 실제 적용값은 01-design-system과 02-common-layout의 최신 확정 규칙 및 명시된 예외를 우선합니다.

## 캔버스 장표 배치와 읽기 순서

[canvas-layout.md](canvas-layout.md)를 기준으로 Figma 페이지 전체의 배치를 확인합니다. 아래 기준은 장표 내부의 좌표 검수와 별개입니다.

- 현재 사용자 배치에서 확인한 행·열·간격·그룹 경계와 명시된 예외를 따르는지 확인합니다.
- 목차의 모든 큰 주제 앞에 간지가 있는지, 기존 사용자 간지를 중복 생성하지 않았는지, 장수 산정에 포함했는지 확인합니다.
- 챕터 간지, 하위 주제의 새 행, 별도 표지·회고·마무리 영역과 의도적인 빈칸이 보존되었는지 확인합니다.
- 새 장표가 관련 챕터의 확정된 앞뒤 장표 사이에 들어갔는지, 본문 밖의 임시 영역에 남아 있지 않은지 확인합니다.
- 장표 전체가 겹치거나 서로 다른 챕터에 섞이지 않는지, 승인된 장표에 누락·중복이 없는지 확인합니다.
- 원고의 발표 순서, 캔버스 읽기 순서, 표시용 순번·페이지 번호·목차 범위가 일치하는지 확인합니다. 기존 식별자와 새 순번의 대응도 유지합니다.
- 이동한 장표의 노드 ID와 사용자가 편집한 내용·디자인이 유지되었는지 확인합니다. 번호를 표시하지 않는 장표와 별도 작업용 자료도 각자의 규칙대로 처리했는지 확인합니다.
- 페이지 전체 배치와 영향을 받은 챕터 경계를 화면으로 확인합니다. 확인한 대상과 남은 예외를 구분하며, 고립된 본문 장표가 있으면 배치 완료로 판단하지 않습니다.

## 화면과 타이포그래피

- 모든 페이지가 1920×1080px인지 확인합니다.
- 제작한 모든 텍스트에 Pretendard Variable을 사용했는지 확인합니다.
- 제목·부제목·챕터명·본문·페이지 번호·출처의 폰트 크기·굵기·행간·색상이 역할별로 일관되는지 확인합니다.
- 폰트 대체, 자동 축소, 텍스트 넘침·겹침·잘림·의도하지 않은 줄바꿈이 없는지 확인합니다.

- 전용 샘플의 명시적 예외를 제외하고 간지·목차 기본 제목 48/64px, 핵심 수치·KPI 48/60px, 표·그래프 라벨과 본문·도표 주석 20/25px인지 확인합니다.
- 이미 조정된 샘플 01·03의 텍스트와 본문 계열을 중복 축소하지 않았는지 확인합니다. 출처·페이지 번호는 기존 20/28px와 색상·좌표를 유지합니다.

## 좌표와 정보 밀도

- 일반 페이지는 공통 마스터의 챕터명·제목·부제목·본문 영역을 유지하고, 표지·목차·간지 등은 명시된 예외만 적용했는지 확인합니다.
- 상단 텍스트 사이 박스 간격 5px, 제목 묶음 하단 Y=310부터 본문 시작 Y=360까지의 세로 간격 50px, 제목·본문의 좌우 안전 여백 80px를 구분하여 확인합니다.
- 제목·부제목·챕터명의 좌측 정렬과 본문 그리드의 열 너비·간격을 확인합니다.
- 콘텐츠가 중심부에 모여 있고 불필요한 빈 공간이나 모서리에 흩어진 작은 요소가 없는지 확인합니다.
- 내용이 넘칠 때 글자를 줄이거나 숨기지 않고 내용을 정리하거나 장표를 분리했는지 확인합니다.
- 제목 줄 수와 고정 영역 높이 등 원본 규칙끼리 충돌하면 임의로 통과시키지 않고 확인이 필요한 항목으로 기록합니다.

- 본문 시작점 (80, 360), 카드 내부 콘텐츠 폭 약 466.67px와 3열 합계 1760px를 확인합니다.
- 카드 제목 30/48px, 본문 25/30px, 버튼 라벨 20/20px를 확인합니다.
- 카드 위쪽 번호만 버튼 형태인지, 하단 보조 설명은 20/25px 텍스트로 본문과 20px 떨어져 있는지 확인합니다.
- 카드 제목은 핵심 구절만 Blue 500으로, 카드 본문은 최대한 짧은 핵심 구절만 Bold 700으로 강조했는지 확인합니다.

## 제목 묶음 구조 검수

- [일반 제목 묶음 구조](../02-common-layout/README.md#일반-제목-묶음의-auto-layout-구조)를 기준으로 대상 장표를 전수 검사합니다. 각 장표 ID별 제목 부모 ID·노드 유형·`layoutMode`, 자식 ID·역할·순서·일반 흐름 여부를 읽습니다. GROUP, NONE 프레임, 슬라이드 직속 텍스트 또는 absolute 자식은 겉모양이 같아도 통과시키지 않습니다.
- 부모와 조상까지 보이는 활성 제목 묶음만 검사 대상으로 집계합니다. 숨겨진 과거 안을 합격 근거로 쓰거나 복원하지 않습니다. 적용 대상과 표지·목차·간지 등 전용 유형 예외를 분리하고, 명시적 예외가 있는 속성만 다르게 검사합니다.
- 간격·상하좌우 패딩·정렬·부모 기준점·실제 너비/높이와 부모/자식의 가로·세로 sizing, 텍스트 resize를 원본과 대조합니다. FIXED/HUG/FILL은 역할과 원본에 맞게 확인하며 HUG 여부만으로 합격을 판단하지 않습니다. 빈 예약 슬롯과 삭제된 역할도 현재 사용자 원본에 맞는지 확인합니다.
- 수정 전후 현재 텍스트·스타일 범위·줄바꿈·삭제·숨김, 본문·푸터의 좌표와 크기가 보존됐는지 대조합니다. 최신 사용자 예외가 아닌 경우 공통 마스터를 확인하고, 예외는 이전 고정 좌표로 되돌리지 말고 안전 여백·넘침·비겹침을 검사합니다.
- 구조 수정 뒤 다시 읽어 전체 대상 수 / 구조 합격 수 / 전용 유형·명시적 예외 수 / 미해결 수를 대조합니다. 합격과 예외를 중복 집계하지 않습니다. 구조 미확인·미해결 장표가 있으면 전체 완료라고 말하지 않습니다.
- 대표 장표의 실제 스크린샷을 확인합니다. 각 sizing 변형, 긴 제목, 역할 누락, 두 줄 등 예외를 포함해 간격·잘림·겹침·본문과 푸터의 비이동을 확인합니다. 전수 구조 검사와 화면 확인 장표 수를 따로 보고하며, 일부 화면 확인을 전체 시각 검수로 표현하지 않습니다.

## 푸터와 페이지 번호

- 페이지 번호를 표시하지 않는 페이지 유형에는 번호가 없는지 확인합니다. 번호 산정에는 표시하지 않는 페이지도 포함하는 현재 공통 규칙을 따릅니다.
- 모든 푸터 좌표는 박스 좌측 상단 기준입니다. 페이지 번호 (1720, 1012), W=120, H=28, 우측 정렬과 저작권 (80, 1012)을 확인합니다. 번호의 오른쪽 끝은 X=1840입니다.
- 페이지 번호 색상은 Grey 500 (#8B95A1)인지 확인합니다.
- 출처는 좌측 상단 (80, 984), 높이 28px로 저작권 바로 위에 여백 없이 배치합니다. 저작권과 페이지 번호의 박스 하단은 Y=1040입니다.
- 출처가 페이지 번호 영역을 침범하거나 잘리지 않는지 확인합니다. 학생 장표의 출처는 저자(연도)만 남기고 상세 서지정보는 발표자 노트나 별도 원고에 보존합니다. URL 문자열과 클릭 hyperlink 속성이 모두 제거됐는지 확인하며, 실습·기능 링크는 보존합니다.

- 최종 라이브 캔버스 순서에 사용자가 새로 만든 장표까지 포함되었는지 확인합니다. 과거 장수나 마지막 번호만으로 검수 범위를 제한하지 않습니다.
- 노드 ID별로 최신 순번·실제 화면 제목·푸터 번호·최상위 레이어 이름을 대조합니다. `NN · 실제 제목` 형식의 순번과 우측 하단 페이지 번호가 같은 순번인지, 이름의 제목이 현재 화면 제목과 일치하는지 확인합니다.
- 순번의 중복·누락, 오래된 제목, 번호 표시 예외의 훼손이 없는지 수정 후 다시 읽고 확인합니다. 번호를 숨기는 장표도 전체 순번에는 포함합니다.

## 내용과 근거

- 한 장에 핵심 메시지 하나를 전달하고 제목은 근거에 맞는 결론형 문장인지 확인합니다.
- 문체·줄바꿈·금지 표현은 02-common-layout/text-rules.md의 확정 규칙을 따르는지 확인합니다.
- 수치·단위·기간·계산 결과가 원본 자료와 일치하는지 확인합니다.
- 사용한 외부 자료의 출처를 추적할 수 있는지, 사용자 제공 자료·자체 분석·제안을 구분했는지 확인합니다.
- 제공되지 않은 수치나 출처를 만들지 않았는지 확인합니다. 미확보 자료는 데이터 필요 또는 출처 확인 필요로 남깁니다.

## 표지와 헤더 로고

- 기본 텍스트 표지의 콘텐츠 시작점 (80, 388), 너비 1440px, 세로 간격 24px를 확인합니다. 두 줄 제목 기준 제목·부제목·작성자 Y는 388·604·668이며, 전용 표지의 명시적 예외와 구분합니다.
- 사용자가 수정한 제목 줄바꿈·작성자·행사일과 앞·뒤표지별 내용을 보존했는지 확인합니다. 과거 시작점이나 기본 날짜로 덮어쓰지 않습니다.
- 표지·뒤표지·목차·간지를 포함한 대상 장표에 좌상단 작성자 로고와 우상단 교육기관·대상 청중 로고가 빠지거나 중복되지 않았는지 확인합니다. 사용하지 않기로 한 슬롯과 명시된 예외는 제외합니다.
- 헤더 프레임 (80, 50, 1760, 44), 좌측 끝 X=80·우측 끝 X=1840, 원본 로고 비율과 다른 요소와의 비겹침을 확인합니다.
- 현재 발표에서 승인한 로고·위치·비율을 확인합니다.

## 카드와 컴포넌트

- 카드 모서리 4px, 내부 패딩 상하 30px·좌우 40px, 카드 간격 60px와 같은 행의 높이·시작점 정렬을 확인합니다.
- 테두리·표면색·그림자·칩의 모서리는 02-common-layout/components.md에 확정된 값이 있을 때 그 기준으로 확인합니다.
- 이전 첨부의 테두리·칩 기본값 대신 현재 components.md의 테두리 없음·버튼 모서리 5px 규칙을 적용합니다.
- 색상과 강조는 기존 디자인 시스템을 따르는지 확인합니다. 첨부의 오렌지 강조색을 새로 도입하지 않습니다.

- 의미가 다른 텍스트 묶음이 각각 별도 컨테이너인지 확인합니다. 예를 들어 독립적인 발견 세 가지가 하나의 박스나 긴 텍스트 노드에 합쳐져 있지 않아야 하며, 같은 묶음의 제목·설명은 함께 있어야 합니다.
- 같은 역할의 컨테이너끼리 모서리·패딩·간격·정렬이 일치하는지 확인합니다. 선택형 내용 그룹 컨테이너는 모서리 4px·상하좌우 패딩 24px·그룹 사이 간격 20px이며, 샘플 03 단계 카드의 패딩·간격과 구분합니다.
- 컨테이너 분리 후에도 원본 그림·스크린샷의 비율과 필요한 정보, 이야기 흐름에 맞는 다이어그램이 보존되었는지 확인합니다. 모든 장표를 같은 카드 그리드로 획일화하지 않았는지, 텍스트가 겹치거나 잘리거나 축소되지 않았는지 확인합니다.

## 내보내기와 완료 판단

- 내보낸 결과에서도 좌표·폰트·이미지 비율·페이지 순서가 유지되는지 확인합니다.
- 요청한 형식과 편집 가능 요소가 실제 결과물에서 지원되는지 확인합니다.
- 오류는 해당 장표와 항목을 기록하고 수정 후 다시 확인합니다.
- 실제 확인한 범위와 미확인 사항을 구분합니다. 미해결 오류나 도구 제한이 있으면 검수 완료로 표현하지 않습니다.

## 교육용 비교·활동·게임 안내 추가 검수

- 공통 기준, 후보, 각 후보별 평가, 최종 선택이 한눈에 구별되는지 확인합니다. 비교 행렬은 후보 수 × 기준 수의 대응 셀이 모두 있어야 합니다.
- 설명 장표와 적용 사례가 같은 항목을 쓰는지, 비교 개념과 통합 방법의 시각적 위계가 다른지 확인합니다.
- 활동 지시가 앞서 가르친 프레임워크의 필수 항목을 빠뜨리지 않는지 확인합니다. 사용자가 '모두 작성'이라고 한 활동을 임의의 일부 질문으로 축소하지 않습니다.
- 실제 게임의 현재 배포 화면과 안내 장표의 버튼명·행동·진행 상태가 일치하는지 확인합니다. 제출 후 대기 화면과 라운드 종료 결과 화면을 혼동하지 않습니다.
- 복잡한 게임 안내는 한 화면/상태를 한 장에 담고, 실제 캡처와 짧은 행동 안내를 대응시킵니다. 이전 엑셀판·개발 초안 화면을 최종 웹게임 설명으로 남기지 않습니다.
- 스크린샷의 핵심 조작·결과가 잘리지 않고 읽히는지, 번호 핀이 UI를 가리지 않는지 확인합니다. 긴 페이지 전체를 축소해 한 장에 몰아넣지 않습니다.
- 게임이나 인터랙티브 자료도 함께 제작했다면 실제 최대 자릿수, 긴 한국어 문구, 모바일 폭, 제출·대기·결과 전환을 확인합니다. 예: 값 10이 1/0 두 줄로 분리되지 않아야 합니다. 화면 미접속 상태에서 시각 검수 완료라고 말하지 않습니다.
- 수업 데이터에 영향을 주는 제출 대신 별도 테스트 데이터나 읽기 전용 재현 화면을 사용할 때는 실제 학생 결과와 구분합니다.


## 최종 완료 직전: 실제 번호와 시각 자산

- '페이지 정리'는 레이어 이름만 고치는 작업이 아닙니다. 최종 활성 장표의 노드 ID별로 캔버스 읽기 순서·레이어 순서·표시 이름·실제 우측 하단 텍스트를 전수 대조하고, 목차 범위와 본문 안의 다른 페이지 참조도 갱신합니다. 표지의 무번호 관례와 사용자의 삭제·숨김은 유지합니다.
- 검사 개수는 '활성 전체 장수 / 번호 표시 대상 수 / 무번호 예외 수'로 확인합니다. 마지막 번호가 맞는 것만으로 중간 누락·중복이 없다고 판단하지 않습니다.
- 색상·좌표·텍스트 경계의 데이터 검수와 실제 렌더링 검수를 구분합니다. 노드가 존재하거나 크기가 정상인 것만으로 이미지·SVG 로고가 보인다고 판단하지 않습니다. 빈 SVG 프레임, 마스크·패턴 누락, 배경과 같은 색, 잘못된 크롭을 화면에서 확인합니다.
- 새 사례마다 브랜드 식별 로고와 주장을 보여주는 사진/화면이 있는지 따로 확인합니다. 공식 제품 사진을 실제 광고 화면이라고 표시하지 않습니다.
- 사용자가 이미 삽입한 이미지는 보존하며, '원본 확보', '사용자에게 전달', '장표에 삽입', '화면에서 확인' 상태를 구분합니다. 수동 삽입용 파일 전달을 삽입 완료로 보고하지 않습니다.
- 이미지 삽입이 막히면 지원되는 방법과 실패 원인을 확인하고, 같은 실패를 반복하지 않습니다. 사용자가 수동 삽입을 허용하면 원본 파일 또는 공식 원본 링크, 대상 장표와 위치를 제공해 마무리할 수 있게 합니다. 빈 이미지 자리만 남겨 완성본이라고 하지 않습니다.
