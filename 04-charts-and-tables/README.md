# 그래프와 표

실제 데이터와 시각 표현 규칙을 구분합니다. 예시 수치를 실제 발표의 근거로 사용하지 않습니다.

## 입력 양식

- 기간별 추이 차트: [입력]
- 항목별 비교 차트: [입력]
- 구성비 차트: [입력]
- 핵심 항목 강조 방식: [입력]
- 나머지 항목 색상: [입력]
- 축/범례/눈금 표시: [입력]
- 수치 라벨과 소수점 자릿수: [입력]
- 단위/기간/출처 표시: [입력]
- 표 머리글/테두리/정렬: [입력]
- 참고할 그래프 이미지 또는 링크: [입력]
- 참고할 요소: [입력]

## 작성 예시

추이는 선그래프, 비교는 막대그래프. 핵심 항목만 강조색 사용.

## 텍스트 크기

- 01-design-system의 타이포그래피를 적용합니다. 축·눈금·범례·수치 라벨은 Pretendard Variable Medium 500, 20px / 행간 25px입니다.
- 본문·도표 주석은 Regular 400, 20px / 행간 25px를 사용합니다. 핵심 수치·KPI는 Bold 700, 48px / 행간 60px입니다.
- 표 안의 일반 설명은 기본 본문 25px / 행간 30px를 따릅니다. 사용 위치와 역할은 유지합니다.
- 출처는 기존 20px / 행간 28px와 푸터 좌표를 유지합니다.

## 데이터 원칙

- 제공되지 않은 수치를 만들지 않습니다. 누락된 값은 `데이터 필요`로 표시합니다.
- 단위·기간·출처를 확인합니다.
- 축 범위나 시각 효과로 수치 차이를 왜곡하지 않습니다.

[전체 작성 안내로 돌아가기](../README.md)

## 입력 안내

- 필수: 그래프·표·다이어그램 사용 여부 (사용/사용 안 함/AI 판단).
- 조건부: 시각화 목적과 유형 결정 방식 (사용 시. 비교/추이/관계/단계 등).
- 조건부: 데이터 위치·단위·기간·계산 기준 (수치 시각화 시. 실제 값은 09/07 참조).
- 조건부: 노드·관계·단계 또는 일정 정보 (조직도·프로세스·타임라인 사용 시).
- 선택: 강조색·축·범례·라벨·소수점.
- 선택: 표 정렬·테두리·머리글.

이미 기록된 값은 다시 묻지 않습니다. 필요한 값이 없으면 질문하고 이 문서에 반영합니다. 선택 항목은 비워도 되며, 작성 예시는 확정값이 아닙니다.

## 같은 기준으로 비교하기

- '같은 기준으로 비교'는 각 후보를 모든 기준에 대응시켜 보여주는 것입니다. 후보 목록 옆에 공통 체크리스트만 두거나, 한 후보만 평가하고 전체 비교라고 부르지 않습니다.
- 후보를 열, 기준을 행으로 놓는 행렬이면 각 교차 셀에 해당 후보의 근거·차이·확인할 내용을 넣습니다. 자료가 없으면 미확인으로 남기며 빈칸을 임의 점수로 채우지 않습니다.
- 여러 후보 열 위에는 '세그먼트 후보'처럼 열 묶음의 의미를 명시하고, 왼쪽 기준 열에도 '비교 기준'을 표시합니다. 굵은 글씨만으로 상하 위계를 대신하지 않습니다.
- 평가 기준이 누구의 관점인지 분명히 합니다. 예를 들어 고객 문제의 절실함, 우리 팀의 고객 접근 가능성, 시장의 규모·경제성, 팀의 해결 역량은 서로 다른 관점입니다. '접근성'을 UI 사용 편의로 잘못 설명하지 않습니다.
- 높은/중간/낮음 등 등급은 관찰 근거와 판정 기준이 있을 때 사용합니다. 프레임워크 저자가 제시하지 않은 공식 점수·계산식을 만들어 인용하지 않습니다.
- 개념 장표와 사례 장표의 항목·순서·용어를 일치시킵니다. 최종 선택은 필요한 경우 대상 고객뿐 아니라 먼저 해결할 문제까지 적습니다.

## 단계·관계 연결

- 흐름을 나타내는 연결은 기존 덱의 네이티브 벡터·선·화살촉 양식을 따릅니다. 본문 문자열 '->'나 큰 화살표 글자를 장식처럼 끼워 넣어 도식을 대신하지 않습니다.
- 연결의 방향·대상·논리 관계가 분명할 때만 화살표를 씁니다. 단순 비교를 억지로 선형 프로세스로 바꾸지 않습니다.
