# 표지 레이아웃

## 공통 적용 규칙

- 목적에 맞는 표지 유형을 선택하고 앞표지와 뒤표지를 한 쌍으로 사용합니다.
- 캔버스는 1920×1080px, 폰트는 Pretendard Variable로 유지합니다.
- 선택한 Figma 샘플의 요소별 위치·크기·정렬·간격·도형 구성을 기준으로 제작합니다.
- 표지에는 일반 장표의 제목·부제목·본문 고정 마스터 좌표를 적용하지 않습니다. 샘플과 다른 공통 타이포 크기를 일괄 덮어쓰지 않고, 샘플에서 확인한 표지 전용 크기·굵기·행간을 적용합니다.
- 표지 자체의 페이지 번호는 표시하지 않습니다. 전체 페이지 산정에는 포함합니다.
- 명시한 표지 예외 외의 공통 규칙은 유지합니다. 좌상단 작성자 로고·우상단 교육기관 또는 대상 청중 로고는 [공통 헤더 규칙](../02-common-layout/components.md#헤더-로고)을 함께 적용합니다.
- 기본 텍스트 앞·뒤표지의 최신 콘텐츠 시작점과 사용자 수정값은 [02의 기본 텍스트 표지](../02-common-layout/README.md#기본-텍스트-표지--샘플-01)를 따릅니다. 전용 표지 유형에는 아래 선택한 샘플의 명시적 예외만 적용합니다.
- 날짜 영역이 있는 유형은 실제 제작 시점의 한국 시간(Asia/Seoul) 기준으로 넣습니다. 샘플에 적힌 날짜를 그대로 복사하지 않습니다.
- 작성자는 사용자 입력으로 확인합니다. 개인 기본값은 없습니다.

## 1. AI 채용 과제·제안서

### 적용 조건

AI 관련 채용 과제 또는 대상 브랜드에 제출하는 제안서의 앞표지·뒤표지에 사용합니다.

### 기준 파일

- 파일: 사용자 지정 레퍼런스
- 페이지: 표지
- 앞표지: 제안서-표지-Front (사용자 제공 레퍼런스 필요)
- 뒤표지: 제안서-표지-Back (사용자 제공 레퍼런스 필요)

### 도형과 브랜드 로고

- 표지의 시각 요소는 편집 가능한 그라디언트 도형으로 구성합니다.
- 그라디언트는 지원하거나 제안하는 대상 브랜드 로고의 키컬러를 기준으로 구성합니다. 샘플의 기존 브랜드 색을 그대로 고정하지 않습니다.
- 도형의 형태·위치·크기와 그라디언트 방향·색상 정지점·투명도 구성은 샘플을 기준으로 유지하고, 색상을 대상 브랜드에 맞게 변경합니다.
- 브랜드 로고는 공식 브랜드 사이트나 공식 브랜드 자료를 우선 찾아 투명 배경 SVG 또는 PNG를 사용합니다.
- 로고는 샘플의 현재 로고 위치와 표시 영역에 배치하며, 원본 비율을 유지합니다. 가로세로를 따로 늘리거나 불투명 배경 박스를 붙이지 않습니다.
- 정확한 대상 브랜드 또는 사용할 로고를 확인할 수 없으면 임의의 로고를 만들지 않고 필요한 자료만 요청합니다.
- 브랜드 키컬러 적용은 표지의 로고와 그라디언트 도형에 대한 예외입니다. 본문 전체의 Blue·Grey 디자인 시스템을 자동으로 변경하지 않습니다.

### 앞표지 1 · 제안서-표지-Front

| 요소 | 입력·교체 규칙 |
|---|---|
| 위쪽 캡션 | 사용자가 제공한 과제명 또는 제안서명 |
| 제목·부제목 영역 | 슬라이드 전체 내용을 바탕으로 제안의 핵심을 짧게 요약 |
| 브랜드 로고 | 지원·제안 대상 브랜드의 투명 배경 로고 |
| 그라디언트 도형 | 대상 로고의 키컬러 기반 |
| 날짜 | 실제 제작일, 샘플과 같은 YYYY. M. D 형식 |
| 과제전형·제안 정보 | 이번 요청의 정확한 명칭. 제공되지 않은 직무·전형명은 추측하지 않음 |
| 작성자 | [작성자] |

- 샘플의 캡션·주요 문구·하단 정보 위치와 시각적 위계를 유지합니다.
- 하단 정보는 샘플처럼 날짜 | 과제·제안 정보 | 작성자 순서로 구성합니다.
- 요약 문구는 실제 슬라이드에서 뽑고, 근거 없는 성과나 주장을 추가하지 않습니다.
- 긴 문구는 의미를 보존해 간결하게 다듬습니다. 로고나 도형을 침범하도록 늘리지 않습니다.

### 뒤표지 1 · 제안서-표지-Back

| 요소 | 입력·교체 규칙 |
|---|---|
| 위쪽 캡션 | 앞표지와 동일한 과제명 또는 제안서명 |
| 제목·부제목 영역 | 앞표지와 동일한 제안 요약 문구를 기본으로 사용 |
| 브랜드 로고·그라디언트 도형 | 앞표지와 같은 브랜드 기준 |
| 마무리 문구 | 감사합니다. |
| 작성자 | [작성자] |

- 기준 프레임의 배치·크기·간격을 유지합니다.
- 하단 문구는 샘플의 감사합니다. | [작성자] 구성을 사용합니다. 뒤표지 샘플에 없는 날짜를 임의로 추가하지 않습니다.
- 뒤표지는 본문 마지막에 배치합니다. 부록이 있다면 공통 규칙에 따라 뒤표지 다음에 배치합니다.

### 샘플에서 읽어야 할 제작 값

프롬프트를 조립할 때 위 Figma 프레임을 읽어 아래 값을 실제 수치로 포함합니다. 이 문서에는 아직 실측하지 않은 좌표나 크기를 임의로 적지 않습니다.

- 각 요소의 프레임 기준 X/Y, 너비·높이, 정렬
- 캡션·제목·부제목·날짜·작성자의 글자 크기·굵기·행간·색상
- 바깥 여백, 요소 사이 간격, 컨테이너 내부 패딩
- 로고 표시 영역과 원본 비율 유지 방식
- 그라디언트 도형의 형태·크기·위치·채움 구성

폰트가 다른 경우 Pretendard Variable로 교체한 뒤 줄바꿈과 겹침을 확인합니다. 프레임 밖의 잔여 요소는 사용하지 않습니다. 샘플에 접근하지 못하면 실측값을 확인한 것처럼 쓰지 않고 미확인으로 표시합니다.

## 2. 자기소개·포트폴리오

### 적용 조건

작성자의 전문 분야·경험·프로젝트를 소개하는 자기소개 또는 포트폴리오에 사용합니다. 채용 지원용이라도 과제 제안이 아니라 본인의 경험 소개가 목적이면 이 유형을 선택합니다.

### 기준 파일

- 파일: 사용자 지정 레퍼런스 / 페이지: 표지
- 앞표지: 자기소개-표지-Front (사용자 제공 레퍼런스 필요)
- 뒤표지: 자기소개-표지-Back (사용자 제공 레퍼런스 필요)
- 두 프레임 모두 1920×1080px입니다.

### 앞표지 1 · 자기소개-표지-Front

| 요소 | 적용 규칙 |
|---|---|
| 메인 제목 | PORTFOLIO를 기본으로 유지. 자기소개 등 별도 제목을 사용자가 지정하면 교체 |
| 소개 문장 | 사용자가 제공한 소개 문장을 사용하고, 수정 요청이 있으면 실제 경력·발표 내용에 근거해 작성 |
| 전문 분야 키워드 |  사용자 제공 전문 분야로 교체 |
| BASE | 사용자 제공 전문 분야. 예: 분야 A · 분야 B |
| CONTACT | 사용자가 공개를 허용한 연락처만 사용. 임의 생성·변경하지 않음 |
| 작성자 | [작성자] |

### 뒤표지 1 · 자기소개-표지-Back

- 메인 제목은 샘플의 Thank you.를 기본으로 사용합니다.
- 소개 문장·전문 분야 키워드·BASE·CONTACT는 앞표지와 같은 내용으로 유지합니다.
- 뒤표지 프레임의 위치·크기·간격·정렬을 따릅니다.
- 본문 마지막에 배치하고, 부록이 있으면 뒤표지 다음에 배치합니다.

### 타이포그래피와 시각 구성

| 역할 | 폰트 | 샘플 크기 | 샘플 굵기 |
|---|---|---|---|
| PORTFOLIO / Thank you. | Pretendard Variable | 100px | Black 900 |
| 소개 문장 | Pretendard Variable | 35px | 혼합 서식: 구간별 굵기를 샘플에서 읽어 유지 |
| 전문 분야 해시태그 | Pretendard Variable | 25px | Regular 400 |
| BASE / CONTACT 라벨 | Pretendard Variable | 20px | SemiBold 600 |
| 전문 분야·연락처 | Pretendard Variable | 20px | Light 300 |

- 위 수치는 확인한 샘플 기준입니다. 제작 시 최신 샘플의 좌표·행간·자간·색상·텍스트 구간별 강조·배경을 함께 읽어 적용합니다.
- 폰트는 Pretendard Variable로 통일합니다.
- 자기소개 유형에는 제안서 유형의 대상 브랜드 로고·키컬러 그라디언트 도형 규칙을 자동 적용하지 않습니다.
- 현재 샘플에는 날짜 영역이 없으므로 날짜를 임의로 추가하지 않습니다.
- 샘플의 구성을 유지하고 실제 텍스트만 필요한 범위에서 바꿉니다. 연락처는 최신 사용자 제공 값이 있으면 그 값을 우선합니다.
- 최종 프롬프트에는 선택한 앞·뒤 표지의 실제 제작 값을 읽어서 함께 넣습니다. 접근하지 못한 값은 추측하지 않습니다.

## 유형을 추가하는 방법

- 새로운 목적은 ## 3. 목적명처럼 다음 번호 형식으로 추가합니다.
- 같은 목적의 다른 디자인은 앞표지 2·뒤표지 2처럼 구분합니다.
- 각 유형에 적용 조건, 정확한 프레임 이름과 직접 링크, 유지할 요소와 교체할 요소를 기록합니다.

## 최종 프롬프트에 포함하기

선택한 유형의 실제 규칙과 Figma에서 읽은 제작 값을 [장표 유형] 구역에 함께 넣습니다. 파일 링크만 전달하지 않습니다. 브랜드 로고 등 별도 첨부가 필요한 자료도 명시합니다.
